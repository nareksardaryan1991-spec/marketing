# Marketing

Приложение для заказа маркетинговых услуг: клиент регистрируется, заполняет анкету
о бизнесе, выбирает пакет (посты, рилсы, истории, реклама), оплачивает, а команда
(сотрудники + AI-помощник) делает материалы и отправляет их клиенту на согласование.

Языки интерфейса: русский, армянский, английский.

## Состояние проекта (30 сентября 2026)

Приложение **работает онлайн**: https://nareksardaryan1991-spec.github.io/marketing/
(сайт — GitHub Pages, сервер — Supabase). Код: https://github.com/nareksardaryan1991-spec/marketing
(публичный репозиторий; каждое изменение в `main` само обновляет сайт). Весь путь заказа
на живом сервере руками ещё не пройден. Для показа без сервера есть просмотровая версия
(см. «Быстрый просмотр»).

### Что сделано
- Регистрация: «Я клиент» / «Я сотрудник»; сотрудник ждёт роль от владельца.
- Знакомство клиента — разговор с агентами: 10 коротких вопросов по одному на экран, ответы сразу
  сохраняются в профиль бизнеса (`businesses.onboarded_at` — знакомство пройдено). После знакомства AI
  бесплатно делает 3 примера постов и контент-план на неделю (`welcome_kits`, один раз на клиента),
  с пометкой «черновик AI, менеджер ещё не проверял». Функция `client-ai`.
- Кабинет клиента: «Ваша команда» (статус каждого агента по настоящим задачам), «Идеи от команды»
  (2–3 в неделю по профилю, `task_ideas`; «Принять» создаёт заказ из одной позиции), подсказки с
  кнопкой вместо пустых списков.
- Анкета бизнеса и профиль бизнеса («мозг» агентов): сайт, соцсети, тон, аудитория, примеры удачных
  постов, логотип (bucket `brand`) и до 5 фирменных цветов. Все AI-функции получают профиль целиком
  (`supabase/functions/_shared/business.ts`); дизайнер берёт акцент из фирменных цветов и ставит логотип
  на картинку. У клиента на главной одна карточка «Ваш бизнес» с процентом заполненности — вход в профиль.
- Заказ по площадкам Instagram / Facebook / TikTok + общие услуги; своя цена на каждой
  площадке; разово или ежемесячно; кто публикует (команда / автоматически / клиент).
- Оплата ArCa и Idram (сейчас тестовый режим), повтор и напоминание о продлении.
- Задачи: назначение, срок, бриф, версии материалов, внутренняя проверка, AI-черновики.
- Согласование клиентом (одобрить / правки), чат по заказу с AI-подсказкой ответа.
- AI-помощник сотрудника: «Мой день» на главной (план работы по своим задачам и срокам,
  менеджеру — ещё и по команде) и «Помощник по задаче» (разбор брифа и правок клиента,
  шаги для своей роли, вопросы). Видит только то, что разрешено самому сотруднику.
- AI-агенты по ролям (экран «🤖 AI-агенты»), пять персонажей со своим именем, цветом и аватаром:
  Ани — SMM (тексты, хэштеги, время, контент-план), Лилит — дизайнер, Арам — сценарист (рилсы,
  TikTok и план съёмки), Арсен — таргетолог, Сона — SEO. Аватары пока временные SVG
  (`apps/mobile/assets/agents/`); финальную картинку положить туда и поменять `require` в
  `src/lib/agents.ts`. Экран агента — чат: пишете своими словами («создай дизайн: стоит человек,
  фон — море») → «Отправить» → агент сразу делает и показывает результат; кнопки «Скопировать»,
  «Открыть / скачать», «В задачу…» (результат становится версией на проверке у менеджера,
  с меткой «🤖 AI-…»). Агент помнит последние 3 сообщения чата — можно уточнять. Дизайнер рисует
  сцену генератором (OpenAI, секрет `IMAGE_API_KEY`), надпись — только если попросили, поверх,
  чёткая на армянском. В задаче есть и блок «Поручить AI-агенту» — версия по брифу задачи. AI-менеджер
  готовит по заказу брифы, исполнителей и сроки — применяется кнопкой. Лимит — 30 запусков
  в день на человека.
- Чат команды: общий (штатные) + личные беседы (включая фрилансеров).
- Чаты как в Telegram (все: по заказу и команды): общий список «Чаты» с поиском и счётчиками,
  фото, видео, файлы, голосовые, ответ с цитатой, пересылка, правка, удаление (оригинал видит
  владелец), реакции, закреплённое, две галочки «прочитано», «в сети / был(а)», «печатает…»,
  фон на выбор (узоры или своё фото). На компьютере — список слева, чат справа.
- Звонки из чата: 📞 аудио и 🎥 видео через Jitsi; собеседнику — «Присоединиться» и уведомление.
- Доска задач (колонки: новые → в работе → на проверке → у клиента → к публикации → опубликовано),
  фильтры по исполнителю, клиенту, «просроченные»; сроки подсвечены (просрочено / сегодня / завтра).
- Напоминания о сроках в 09:00: исполнителю — «завтра» и «сегодня», о просроченных — ещё и менеджерам.
- Панель владельца: выручка за месяц (только владельцу), заказы, задачи, нагрузка команды,
  просроченные задачи; утренняя сводка владельцу в 09:00 в Telegram / push.
- Публикация по расписанию, контент-календарь, автопубликация в Instagram.
- Отчёты: подписчики, охват, цифры по каждому посту (из Instagram).
- Уведомления в Telegram и push на языке получателя.
- Владелец: единственный, кто назначает роли; экран «Услуги и цены».
- Личный кабинет у каждого (клиент и сотрудник): имя, телефон, «о себе», фото профиля,
  обложка (фото или цвет на выбор), смена пароля. Фото — в публичном bucket `avatars`,
  каждый загружает только в свою папку. Там же, под шапкой, кнопка «🔔 Уведомления»
  (Telegram и push); с главного экрана она убрана. Кабинет открывается нажатием на своё имя.
- Согласование «как в Instagram» (идеи Planable, Sked, 99 Dollar Social, Kitchen):
  экран «На согласовании». Материал показан как пост (4:5, карусель), Reels или история (9:16)
  с аватаром и названием бизнеса; «Сетка профиля» показывает, как посты лягут в ленту.
  Есть «Одобрить всё». Правки можно дать точками на кадре (на видео — с секундой) и комментарием.
  Команда видит точки на той версии, к которой их поставили, и превью «как увидит клиент».
- Срок ответа клиента: через N дней молчания материал одобряется сам (N задаёт владелец в
  «Услуги и цены», по умолчанию 3, 0 — выключено). Клиенту приходит одно напоминание обо
  всём, что ждёт: на следующий день после отправки и за день до срока. Команде приходит
  «одобрено автоматически».
- Промокоды (владелец, «Услуги и цены»): процент или сумма, лимит использований, срок.
  Скидка идёт только на услуги и только на этот заказ (повтор и продление — по полной цене),
  использование засчитывается после оплаты.
- Квитанции: у каждой оплаты номер; «Мои оплаты» в личном кабинете клиента и кнопка
  «Квитанция» в заказе; «Сохранить PDF» открывает окно печати.

### Решения, принятые с заказчиком
| Вопрос | Решение |
|---|---|
| Платформа | мобильное приложение + веб из одного кода (Expo) |
| Языки | русский, армянский, английский |
| Кто делает работу | люди + AI-помощник (AI пишет черновики, человек проверяет) |
| Оплата | ArCa / Idram, драмы; разово и ежемесячно; рекламный бюджет — через агентство |
| Площадки в заказе | Instagram, Facebook, TikTok; у каждой своя цена |
| Правки клиента | без лимита, каждая правка — новая версия |
| Публикация | все варианты: команда, автоматически (только Instagram), клиент сам |
| Роли | владелец (один), менеджер, дизайнер, видеограф, монтажёр, фотограф, копирайтер, SMM, таргетолог, SEO, фрилансер, клиент |
| Регистрация | сотрудник ждёт роль от владельца; клиент — сразу, без одобрения |
| Чат команды | общий + личные; фрилансеры — только личные |
| Уведомления | Telegram + push + web push (сайт; на iPhone — через «На экран „Домой“»); WhatsApp — позже |
| Чаты | все (по заказу и команды) — как в Telegram: общий список, фото/видео/файлы, голосовые, ответ и пересылка, правка и удаление, реакции, закреп, две галочки, «в сети / был(а)», «печатает…» |
| Удаление сообщений | исчезает у всех; оригинал (текст и файлы) видит только владелец |
| Фон чатов | каждый выбирает сам: готовые узоры или своё фото |
| Звонки | аудио и видео из чата; сначала через Jitsi (бесплатно), позже можно встроенные (LiveKit) |
| Работа команды | доска задач по этапам, подсветка и напоминания о сроках |
| Для владельца | панель: деньги только владельцу, менеджерам — без денег; утренняя сводка в 09:00 |
| Отправка в GitHub | только с разрешения заказчика (отправка в `main` сразу меняет сайт) |
| Согласование | превью как в Instagram, «одобрить всё», точки правок; автоодобрение через N дней (по умолчанию 3) |
| Промокоды | только на услуги и один заказ; продление по полной цене |
| Отложено | WhatsApp, генерация картинок AI, публикация на Facebook-страницы, автосписание подписки с карты |

### Что осталось
1. **Полноценный запуск на этом компьютере:** установить Docker
   (`sudo apt install -y docker.io && sudo usermod -aG docker $USER`, перезайти),
   затем `./scripts/local.sh`, пройти весь путь руками и исправить найденное.
2. **Данные от заказчика:** реальные цены; проверить армянские тексты
   (`apps/mobile/src/i18n/hy.ts`) носителем языка; ключ Anthropic; Telegram-бот.
3. **Облако** (состояние на 30.09.2026) — см. «Сервер Supabase сейчас» ниже.
   Осталось: ключи сервисов (Telegram-бот, Anthropic, Instagram, `PAYMENT_MODE`,
   `APP_RETURN_PREFIXES`) и сайт на своём домене.
4. **Долгие внешние дела:** политика конфиденциальности и оферта; договор эквайринга
   ArCa / Idram; приложение Meta и App Review для Instagram.
5. **Мобильные приложения:** Android APK/AAB собираются на GitHub (см. «Android-приложение»);
   дальше проверка на телефонах, Google Play, push (Firebase). iPhone — см. «Установка на iPhone».
6. **Web push:** сервер отправляет без ошибок (проверено 30.09.2026). Осталось заказчику
   подтвердить, что уведомление приходит на iPhone при закрытом приложении.
7. **Выложено 01.10.2026:** личный кабинет, чаты как в Telegram, звонки, доска задач,
   панель владельца, сроки, согласование «как в Instagram», автоодобрение, промокоды и
   квитанции — в GitHub (сайт обновлён), миграции `0014`–`0018` и функции
   `ai-reply`, `notify-dispatch` — на сервере.
8. **Проверить после выкладки:**
   - звонки: на meet.jit.si первый вошедший должен войти через Google/GitHub; если мешает —

   - «Сохранить PDF» на телефоне (системное окно печати, `expo-print` — нужна новая сборка

- Формат запросов сверить с документацией, которую выдадут банк и Idram при подключении.
- Ежемесячная оплата сейчас — это новый заказ каждый месяц (см. «Ежемесячные заказы»).
  Автосписание с сохранённой карты подключим, когда банк включит эту функцию.

## Работа команды и AI

Путь задачи:

```
новая → назначена → в работе → на проверке → у клиента → одобрена → публикация → опубликована
                        ↑______________|           |
                        ↑__________________________| (клиент попросил правки)
```

- **Менеджер** на главной видит «На проверку», «Клиент просит правки», «Пора
  публиковать» и «Новые задачи». В задаче он назначает исполнителя, срок и пишет
  задание.
- **Исполнитель** (сотрудник или фрилансер) видит свои задачи и бриф клиента, пишет
  текст, загружает файлы (фото, видео, PDF) и отправляет на проверку. Каждая отправка
  сохраняется отдельной версией.
- **Фрилансер** видит только свои задачи и данные этих клиентов, чат с клиентом не видит.
- **AI-помощник** в задаче пишет черновик текста поста, идеи, сценарий рилса или
  контент-план с учётом анкеты клиента, задания и замечаний к прошлым версиям.
  Черновик проверяет человек.

AI использует модель Claude Opus 5.5. Каждый запрос записывается в таблицу
`ai_generations` с числом токенов, так что расходы видны.

Файлы хранятся в приватном хранилище Supabase. На бесплатном тарифе один файл
может быть не больше 50 МБ; для длинных видео понадобится платный тариф.

## Согласование, чат и уведомления

- Когда менеджер отправляет работу клиенту, у клиента на главной появляется
  «Ждут вашего согласования». Клиент нажимает **«Одобрить»** или **«Попросить правки»**
  (с комментарием).
- **Чат** у каждого заказа: клиент ↔ штатная команда. У команды есть кнопка
  «AI-подсказка ответа».
- **Все чаты — как в Telegram.** Экран «Чаты» (кнопка на главной у всех, со счётчиком) собирает
  чаты заказов, общий чат команды и личные беседы; поиск, последнее сообщение, время, галочки.
  В чате: 📎 — фото/видео или файл (до 10 штук, до 50 МБ), 🎤 — голосовое (нажать — запись,
  ➤ — отправить). Долгое нажатие (на компьютере — правая кнопка мыши) открывает меню:
  реакции, «Ответить», «Переслать», «Копировать», «Изменить», «Закрепить», «Удалить».
  На телефоне свайп сообщения вправо — «Ответить». Удалённое сообщение исчезает у всех;
  оригинал (текст и файлы) видит только владелец. Две синие галочки — собеседник прочитал;
  в чате заказа клиент видит «прочитано командой», команда — «прочитано клиентом».
  «В сети» — приложение открыто (отметка раз в минуту), «печатает…» — через realtime.
  Фон чатов каждый выбирает в «Личном кабинете»: 8 готовых узоров или своё фото
  (узор рисует `scripts/make-chat-pattern.mjs`).
  Устроено так: миграция `0015_chat_telegram.sql` (вложения, ответы, пересылка, правка и удаление
  через функции, реакции `chat_reactions`, закреп, `order_chat_reads`, `my_chats`, `chat_info`),
  файлы — приватный bucket `chat-files`, путь `<order|team>/<id чата>/<id автора>/<файл>`;
  открыть файл может тот, кто видит сообщение с ним (так работает и пересылка).
  В приложении — `src/components/chat/` и `src/lib/useChat.ts`.
- **Звонки.** В шапке каждого чата 📞 (аудио) и 🎥 (видео). Нажатие сразу открывает комнату
  Jitsi (в браузере — новая вкладка, на телефоне — приложение Jitsi или браузер) и пишет в чат
  карточку звонка с кнопкой «Присоединиться»; собеседнику приходит уведомление
  «📞 Звонок от …» со ссылкой (Telegram, push, web push). Комната — `marketing-` + 20 случайных
  символов, база принимает только такой формат (миграция `0016_calls.sql`).
  Сервер звонков по умолчанию — бесплатный https://meet.jit.si: там тот, кто открывает комнату
  первым, входит через Google/GitHub и становится ведущим, остальные ждут его. Если это мешает —
  бесплатный тариф 8x8 JaaS или свой сервер Jitsi: адрес задаётся переменной репозитория
  `EXPO_PUBLIC_JITSI_URL` (приложение) и секретом `JITSI_URL` у функций (ссылка в уведомлениях).
- В чатах на компьютере сообщение уходит по **Enter** (Shift+Enter — новая строка).
  О новом сообщении от другого человека сообщает громкий сигнал — рёв мотоцикла
  (`scripts/make-motorcycle-sound.mjs`); в браузере он звучит после первого нажатия на странице.
- **Чат команды** (кнопка на главной у сотрудников, со счётчиком непрочитанных):
  общий чат штатной команды и личные беседы — например, администратор с любым
  работником. Фрилансеры участвуют только в личных беседах; клиенты этот чат не видят.
- **Уведомления** приходят в Telegram (клиент подключает в личном кабинете → «🔔 Уведомления»)
  и push, на языке получателя:

| Событие | Кому |
|---|---|
| Задача назначена (и задача команды при создании) | исполнителю |
| Работа отправлена на проверку | менеджерам |
| Менеджер вернул на доработку | исполнителю |
| Материал готов к согласованию | клиенту |
| Клиент одобрил / попросил правки | менеджерам и исполнителю |
| Пора публиковать | менеджерам и SMM (или клиенту в режиме «Я сам») |
| Опубликовано | клиенту |
| Автопубликация не удалась | менеджерам |
| Пора продлить ежемесячный заказ | клиенту |
| Новое сообщение от клиента | менеджерам |
| Новое сообщение от команды | клиенту |
| Сообщение в чате команды | участникам беседы (в общем — всей штатной команде) |
| Звонок в чате | собеседнику (со ссылкой «Присоединиться») |
| Срок задачи завтра / сегодня | исполнителю (в 09:00 по Еревану) |
| Задача просрочена | исполнителю и менеджерам, каждый день в 09:00 |
| Задачу команды вернули (с комментарием) / приняли | исполнителю |
| Утренняя сводка: заказы, выручка, работы за вчера | владельцу, в 09:00 |

**Web push** — уведомления на сайте: в браузере на компьютере и Android, а на iPhone
(iOS 16.4+) — в сайте, добавленном через Safari «Поделиться» → «На экран „Домой“».
Человек включает их кнопкой «Включить push» в личном кабинете → «🔔 Уведомления» (Safari спрашивает
разрешение только по нажатию). Нажатие на уведомление открывает нужный экран.
Устроено так: `apps/mobile/public/sw.js` (service worker) и `manifest.webmanifest`,
подписка — `src/lib/push.web.ts`, подписки хранятся в `web_push_subscriptions`,
отправляет `notify-dispatch`. При выходе из аккаунта браузер отписывается.
Ключи VAPID лежат в `~/Documents/marketing-keys/vapid.env`:
- публичный — переменная репозитория `EXPO_PUBLIC_WEB_PUSH_KEY` (и в `apps/mobile/.env.local`);
- в секретах Supabase — `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` и `VAPID_SUBJECT`
  (адрес сайта). Без них web push не отправляется, Telegram работает как раньше.
Если ключи сменить, браузеры переподпишутся при следующем входе в приложение.

**Уведомления не уходят вовсе** (в таблице `notifications` пустой `sent_at` и нет `error`):
у базы нет секретов для вызова `notify-dispatch`. Исправляет `./scripts/enable-notifications.sh`
(то же делает шаг 4 `setup.sh`).

**Push в приложении** работает только в собранном приложении (EAS Build), не в Expo Go
на Android. Нужны `npx eas-cli@latest init` (добавит projectId) и ключи Firebase/Apple
при сборке. До этого уведомления приходят в Telegram и web push.

## Доска задач и панель владельца

- **Доска задач** (кнопка «🗂 Доска задач» на главной у сотрудников): менеджер и владелец видят
  все задачи, сотрудник — свои. На компьютере колонки рядом, на телефоне — вкладки. Фильтры:
  «🔴 Просроченные», исполнитель, клиент. Статус меняется на экране задачи, как раньше.
- **Сроки:** просрочено — красным, сегодня — оранжевым, завтра — жёлтым (и в списках на главной).
  Просроченной считается задача, которая ещё за командой (не у клиента и не одобрена).
- **Напоминания** (`process_due_reminders`, pg_cron каждый день в 05:00 UTC = 09:00 Ереван):
  «завтра срок» и «сегодня срок» — исполнителю, «просрочено» — исполнителю и менеджерам
  (каждый день, пока не сдадут). Одна задача — одно напоминание в день (`tasks.due_reminded_on`).
- **Панель владельца** (кнопка «📊 Панель владельца» у владельца и менеджеров, функция
  `owner_dashboard`): выручка за месяц и сравнение с прошлым (только владельцу), оплаченные
  заказы, активные клиенты, задачи по этапам, нагрузка каждого сотрудника, список просроченных.
- **Утренняя сводка** (`process_daily_digest`, то же время): владельцу — новые заказы, выручка,
  сданные и опубликованные работы за вчера и что сейчас ждёт (проверка, без исполнителя, просрочено).
  Нажатие на уведомление открывает панель.

## Публикация и контент-календарь

- У задачи задаются **дата и время публикации**. Всё запланированное видно в
  **контент-календаре**: клиент видит свои публикации, команда — все.
- Кто публикует, выбирается в заказе:
  - **«Наша команда»** — в назначенное время менеджерам и SMM приходит «Пора
    публиковать»; они публикуют и нажимают «Отметить опубликованным» (можно со ссылкой).
  - **«Автоматически»** — публикует сервер в Instagram (см. ниже). Без подключённого
    Instagram работает как «Наша команда».
  - **«Я сам»** — напоминание приходит клиенту; он скачивает файлы и сам отмечает
    публикацию.
- Когда опубликовано всё, заказ получает статус «Выполнен».
- **Ежемесячные заказы:** через 30 дней после оплаты клиенту приходит напоминание
  о продлении; кнопка «Повторить заказ» создаёт такой же заказ по текущим ценам.

## Автопубликация в Instagram

Клиент подключает Instagram в разделе «Соцсети» (нужен профессиональный аккаунт:
бизнес или автор; Facebook-страница не нужна). Дальше сервер публикует сам:

| Услуга | Файлы | Что выйдет |
|---|---|---|
| Пост | 1 фото | пост |
| Пост | 1 видео | рилс |
| Пост | 2–10 файлов | карусель |
| Рилс | видео | рилс |
| История | фото или видео | история |

- Instagram принимает фото только в **JPEG**, видео — **MP4/MOV**. Приложение само
  переводит фото (PNG, HEIC, WebP…) в JPEG при загрузке и уменьшает до 1440 px по ширине.
  Для поста исполнитель сразу видит предупреждение, если пропорции фото не подходят
  для ленты (нужно от 4:5 до 1.91:1).
- Видео Instagram обрабатывает несколько минут: сервер проверяет каждые 5 минут и
  публикует, когда готово.
- Если не получилось (не тот формат, ошибка Instagram, обработка дольше 2 часов),
  менеджеры получают уведомление с причиной. Можно опубликовать вручную или исправить
  файлы и заново поставить дату.
- Токен доступа хранится только на сервере и продлевается автоматически.
- Facebook-страницы пока не поддерживаются.

## Отчёты

Раздел **«Отчёт»** у клиента (у менеджера — кнопка «Отчёт» в анкете клиента) за
последние 30 дней:

- подписчики и их изменение, охват, просмотры, взаимодействия аккаунта;
- охват каждой нашей публикации (лучшая выделена) с лайками, комментариями,
  сохранениями и репостами; нажатие открывает пост;
- сводка работы: опубликовано, запланировано, в работе.

Цифры собираются из Instagram каждые 6 часов (истории Instagram отдаёт только первые
24 часа, поэтому чаще, чем раз в сутки). Публикации, сделанные вручную, находятся по
ссылке, указанной при отметке «Опубликовано». Для статистики нужно разрешение
`instagram_business_manage_insights`; если аккаунт подключён без него, в отчёте будет
просьба переподключить Instagram.

### Настройка Meta (один раз)

1. https://developers.facebook.com → **Create App** → тип **Business**.
2. Добавьте продукт **Instagram** → **API setup with Instagram login**. Там будут
   **Instagram App ID** и **Instagram App Secret** — их спросит `./scripts/setup.sh`.
3. В «Business login settings» укажите **Redirect URL**:
   `https://<ref>.supabase.co/functions/v1/instagram-callback`
4. **Пока приложение Meta в режиме разработки**, подключать можно только аккаунты,
   добавленные как тестировщики (App roles → Roles → Instagram Testers).
   Для реальных клиентов нужен **App Review** на разрешения
   `instagram_business_basic`, `instagram_business_content_publish` и
   `instagram_business_manage_insights`: понадобятся
   политика конфиденциальности на сайте, видео с демонстрацией и верификация бизнеса.
   Обычно это занимает от нескольких дней до нескольких недель.

## Роли и регистрация

- **Владелец** (`admin`) — один на компанию. Только он назначает роли; всё, что может
  менеджер, может и он.
- **Сотрудники:** менеджер, дизайнер, видеограф, монтажёр, фотограф, копирайтер,
  SMM-специалист, таргетолог, SEO-специалист — видят всех клиентов и общий чат команды.
- **Фрилансер** — только свои задачи и данные этих клиентов, личные чаты.
- **Сотрудник** (`employee`) с должностью (дизайнер, фотограф… — вписывает владелец на экране
  «Команда») — только свои задачи и бизнесы клиентов этих задач, личные чаты. Заказов, сумм,
  платежей, панели владельца и AI-агентов не видит; пожелания клиента к заказу получает через
  `task_order_notes`.
- **Клиент** — свой бизнес, заказы, согласование, чат по заказу.

При регистрации человек выбирает **«Я клиент»** или **«Я сотрудник агентства»**.
Сотрудник попадает на экран ожидания, владелец получает уведомление и назначает роль
на экране «Команда» (блок «Ждут роли») — после этого у сотрудника открывается работа.
Выбрать себе роль при регистрации нельзя.

## Как это устроено внутри

- Права доступа проверяет база (Row Level Security): клиент видит только своё,
  фрилансер — только свои задачи, токены Instagram не видит никто, кроме сервера.
- Смена статусов идёт через функции базы (`create_order`, `assign_task`,
  `client_decide`, `mark_published`…), так что правила не обойти из приложения.
- Уведомления: база пишет строку в `notifications` и сразу вызывает функцию
  `notify-dispatch`. Расписание (публикации, продления, автопубликация, сбор
  статистики) — через pg_cron.
  Адрес проекта и секреты для этих вызовов лежат в Supabase Vault (их кладёт
  `setup.sh`).
