# Marketing

Приложение для заказа маркетинговых услуг: клиент регистрируется, заполняет анкету
о бизнесе, выбирает пакет (посты, рилсы, истории, реклама), оплачивает, а команда
(сотрудники + AI-помощник) делает материалы и отправляет их клиенту на согласование.

Языки интерфейса: русский, армянский, английский.

## Состояние проекта (30 сентября 2026)

Приложение **работает онлайн**: https://nareksardaryan1991-spec.github.io/marketing/
(сайт — GitHub Pages, сервер — Supabase). Код: https://github.com/nareksardaryan1991-spec/marketing
(публичный репозиторий; каждое изменение в `main` само обновляет сайт). Весь путь заказа
на живом сервере руками ещё не пройден. Для показа без сервера есть просмотровая версия
(см. «Быстрый просмотр»).

### Что сделано
- Регистрация: «Я клиент» / «Я сотрудник»; сотрудник ждёт роль от владельца.
- Анкета бизнеса (редактируется потом в «Мой бизнес»).
- Заказ по площадкам Instagram / Facebook / TikTok + общие услуги; своя цена на каждой
  площадке; разово или ежемесячно; кто публикует (команда / автоматически / клиент).
- Оплата ArCa и Idram (сейчас тестовый режим), повтор и напоминание о продлении.
- Задачи: назначение, срок, бриф, версии материалов, внутренняя проверка, AI-черновики.
- Согласование клиентом (одобрить / правки), чат по заказу с AI-подсказкой ответа.
- Чат команды: общий (штатные) + личные беседы (включая фрилансеров).
- Публикация по расписанию, контент-календарь, автопубликация в Instagram.
- Отчёты: подписчики, охват, цифры по каждому посту (из Instagram).
- Уведомления в Telegram и push на языке получателя.
- Владелец: единственный, кто назначает роли; экран «Услуги и цены».

### Решения, принятые с заказчиком
| Вопрос | Решение |
|---|---|
| Платформа | мобильное приложение + веб из одного кода (Expo) |
| Языки | русский, армянский, английский |
| Кто делает работу | люди + AI-помощник (AI пишет черновики, человек проверяет) |
| Оплата | ArCa / Idram, драмы; разово и ежемесячно; рекламный бюджет — через агентство |
| Площадки в заказе | Instagram, Facebook, TikTok; у каждой своя цена |
| Правки клиента | без лимита, каждая правка — новая версия |
| Публикация | все варианты: команда, автоматически (только Instagram), клиент сам |
| Роли | владелец (один), менеджер, дизайнер, видеограф, монтажёр, фотограф, копирайтер, SMM, таргетолог, SEO, фрилансер, клиент |
| Регистрация | сотрудник ждёт роль от владельца; клиент — сразу, без одобрения |
| Чат команды | общий + личные; фрилансеры — только личные |
| Уведомления | Telegram + push + web push (сайт; на iPhone — через «На экран „Домой“»); WhatsApp — позже |
| Отложено | WhatsApp, генерация картинок AI, публикация на Facebook-страницы, автосписание подписки с карты |

## Первый запуск в облаке

1. Создайте проект на https://supabase.com (бесплатный тариф подходит) и запомните
   пароль базы данных.
2. Заранее можно подготовить (или пропустить и добавить позже):
   - ключ **Anthropic API** для AI — https://console.anthropic.com;
   - **Telegram-бота** для уведомлений — в Telegram напишите @BotFather → `/newbot`;
   - **Instagram App ID и Secret** для автопубликации — см. «Настройка Meta» ниже.
3. Из корня проекта:
   ```bash
   ./scripts/setup.sh
   ```
   Скрипт попросит войти в Supabase, спросит ref проекта и ключи, затем сам:
   применит миграции, сохранит секреты, загрузит серверные функции, подключит
   Telegram-бота и запишет настройки приложения в `apps/mobile/.env.local`.
   Уведомления и автопубликация включаются автоматически — ничего не нужно
   настраивать в панели Supabase. Скрипт можно запускать повторно, например чтобы
   добавить пропущенный ключ.
4. Запустите приложение:
   ```bash
   cd apps/mobile
   npm install
   npm start          # затем: w — веб, a — Android, i — iOS
   ```
   На телефоне: установите **Expo Go** и отсканируйте QR-код из терминала.
5. Зарегистрируйтесь в приложении и сделайте себя владельцем компании:
   ```bash
   ./scripts/make-admin.sh you@example.com
   ```
   Владелец один. Остальным людям роли назначает он на экране «Команда».
6. Для удобных тестов: **Authentication → Sign In / Providers → Email** — выключите
   «Confirm email», тогда вход работает сразу после регистрации.

Оплата после установки работает в **тестовом режиме**: вместо банка кнопка
«Оплатить (тест)».

## Онлайн через GitHub

Код лежит в публичном репозитории на GitHub. При каждом обновлении ветки `main`:
- **«Сайт»** (`.github/workflows/web.yml`) проверяет приложение, собирает веб-версию и
  публикует её на GitHub Pages: `https://<логин>.github.io/marketing/`;
- **«Сервер»** (`.github/workflows/supabase.yml`) прогоняет проверки базы и обновляет
  базу и серверные функции в Supabase.

Один раз после `./scripts/setup.sh` (на вопрос «Адрес сайта» — `https://<логин>.github.io`)
заполните в репозитории **Settings → Secrets and variables → Actions**:

| Где | Имя | Откуда |
|---|---|---|
| Variables | `EXPO_PUBLIC_SUPABASE_URL` | `apps/mobile/.env.local` |
| Variables | `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | `apps/mobile/.env.local` |
| Variables | `EXPO_PUBLIC_TELEGRAM_BOT` | `apps/mobile/.env.local` (можно пусто) |
| Variables | `SUPABASE_PROJECT_REF` | ref проекта Supabase |
| Secrets | `SUPABASE_ACCESS_TOKEN` | supabase.com/dashboard/account/tokens |
| Secrets | `SUPABASE_DB_PASSWORD` | пароль базы |

В Supabase: **Authentication → URL Configuration → Site URL** — адрес сайта
`https://<логин>.github.io/marketing/`, иначе ссылки из писем будут вести на localhost.
Пока переменных нет, задачи только проверяют код и ничего не публикуют.

### Android-приложение

**«Android»** (`.github/workflows/android.yml`) запускается вручную: **Actions → Android →
Run workflow**. Через ~20 минут в **Releases** появляются `marketing.apk` (ставить на телефон)
и `marketing.aab` (загружать в Google Play). Последний APK всегда по ссылке
`https://github.com/<логин>/marketing/releases/latest/download/marketing.apk`.

Сборка подписывается ключом `upload.keystore`. Он хранится вне репозитория
(`~/Documents/marketing-keys/`), пароль там же. **Ключ нельзя терять:** с другим ключом
Google Play не примет обновление, а телефоны не поставят его поверх старой версии.
В секретах репозитория нужны `ANDROID_KEYSTORE_BASE64` (файл ключа в base64),
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_PASSWORD`, `ANDROID_KEY_ALIAS` (`upload`).
Имя пакета `com.nareksardaryan.marketing` (`app.json`) после первой загрузки в Google Play не меняется.
Push в сборке пока выключен (нужны EAS projectId и Firebase), уведомления идут в Telegram
и web push на сайте.

**Состояние на 30.09.2026:** секреты заданы, первая сборка (`android-1.0.0-1`) прошла и
подписана своим ключом (`CN=Marketing`). APK ~110 МБ — внутри код для всех типов
процессоров (для Google Play это не важно, для прямой установки можно сделать лёгкий вариант).
На телефоне ещё не проверялось. Резервную копию `~/Documents/marketing-keys/` заказчик
должен сделать сам (флешка / личное облако).

Секреты в GitHub записывает только заказчик: Claude Code это запрещено. В VS Code
команду набирают во встроенном терминале (Ctrl+\`), а не в чате — `!` там не работает.

**Что нужно для Google Play:**
1. Аккаунт разработчика Google Play ($25 один раз, проверка личности). У личного аккаунта
   Google требует закрытый тест: не меньше 12 тестировщиков 14 дней подряд, потом можно
   выпускать для всех; аккаунт организации (нужен D-U-N-S) от этого освобождён.
2. Политика конфиденциальности (ссылка обязательна) и тестовый вход для проверяющих Google.
3. В Play Console: «Безопасность данных», возрастной рейтинг, скриншоты, описание (ru/hy/en).
4. Загрузить `marketing.aab` из Releases; каждая новая загрузка — новый запуск сборки
   (номер растёт сам).
5. Оплата ArCa / Idram разрешена (услуги в реальном мире — не нужна оплата через Google),
   но к проверке она должна работать по-настоящему.

## Заказы и оплата

Клиент выбирает площадки — **Instagram, Facebook, TikTok** — и для каждой отдельно
указывает, сколько постов, историй и рилсов (в TikTok — видео) нужно. Отдельно —
общие услуги: настройка рекламы, выезд на съёмку. Разово или ежемесячно, и кто
публикует. Сумму считает сервер по ценам из базы. После оплаты у каждой единицы
заказа появляется задача: «Instagram · Пост #1», «Facebook · Пост #1»…

### Цены

У каждой площадки **свои** цены. В миграции стоят временные: Instagram — пост
8 000 ֏, история 4 000 ֏, рилс 25 000 ֏; Facebook — 6 000 / 3 000 / 20 000 ֏;
TikTok — видео 25 000 ֏; настройка рекламы 30 000 ֏, выезд на съёмку 40 000 ֏.
Владелец или менеджер меняет их в приложении на экране **«Услуги и цены»**
(блок «Цены по площадкам»): цену, доступность услуги на площадке, названия и описания
на трёх языках. Новая цена действует для новых заказов, оплаченные не меняются.

Клиент может поправить анкету в разделе **«Мой бизнес»**, менеджер — анкету любого
клиента (нажать на клиента в списке на главной).

- Ежемесячная оплата сейчас — это новый заказ каждый месяц (см. «Ежемесячные заказы»).
  Автосписание с сохранённой карты подключим, когда банк включит эту функцию.

## Работа команды и AI

Путь задачи:

```
новая → назначена → в работе → на проверке → у клиента → одобрена → публикация → опубликована
                        ↑______________|           |
                        ↑__________________________| (клиент попросил правки)
```

- **Менеджер** на главной видит «На проверку», «Клиент просит правки», «Пора
  публиковать» и «Новые задачи». В задаче он назначает исполнителя, срок и пишет
  задание.
- **Исполнитель** (сотрудник или фрилансер) видит свои задачи и бриф клиента, пишет
  текст, загружает файлы (фото, видео, PDF) и отправляет на проверку. Каждая отправка
  сохраняется отдельной версией.
- **Фрилансер** видит только свои задачи и данные этих клиентов, чат с клиентом не видит.
- **AI-помощник** в задаче пишет черновик текста поста, идеи, сценарий рилса или
  контент-план с учётом анкеты клиента, задания и замечаний к прошлым версиям.
  Черновик проверяет человек.

AI использует модель Claude Opus 5.5. Каждый запрос записывается в таблицу
`ai_generations` с числом токенов, так что расходы видны.

Файлы хранятся в приватном хранилище Supabase. На бесплатном тарифе один файл
может быть не больше 50 МБ; для длинных видео понадобится платный тариф.

## Согласование, чат и уведомления

- Когда менеджер отправляет работу клиенту, у клиента на главной появляется
  «Ждут вашего согласования». Клиент нажимает **«Одобрить»** или **«Попросить правки»**
  (с комментарием).
- **Чат** у каждого заказа: клиент ↔ штатная команда. У команды есть кнопка
  «AI-подсказка ответа».
- В чатах на компьютере сообщение уходит по **Enter** (Shift+Enter — новая строка).
  О новом сообщении от другого человека сообщает громкий сигнал — рёв мотоцикла
  (`scripts/make-motorcycle-sound.mjs`); в браузере он звучит после первого нажатия на странице.
- **Чат команды** (кнопка на главной у сотрудников, со счётчиком непрочитанных):
  общий чат штатной команды и личные беседы — например, администратор с любым
  работником. Фрилансеры участвуют только в личных беседах; клиенты этот чат не видят.
- **Уведомления** приходят в Telegram (клиент подключает в разделе «Уведомления»)
  и push, на языке получателя:

| Событие | Кому |
|---|---|
| Задача назначена | исполнителю |
| Работа отправлена на проверку | менеджерам |
| Менеджер вернул на доработку | исполнителю |
| Материал готов к согласованию | клиенту |
| Клиент одобрил / попросил правки | менеджерам и исполнителю |
| Пора публиковать | менеджерам и SMM (или клиенту в режиме «Я сам») |
| Опубликовано | клиенту |
| Автопубликация не удалась | менеджерам |
| Пора продлить ежемесячный заказ | клиенту |
| Новое сообщение от клиента | менеджерам |
| Новое сообщение от команды | клиенту |
| Сообщение в чате команды | участникам беседы (в общем — всей штатной команде) |

**Web push** — уведомления на сайте: в браузере на компьютере и Android, а на iPhone
(iOS 16.4+) — в сайте, добавленном через Safari «Поделиться» → «На экран „Домой“».
Человек включает их кнопкой «Включить push» в разделе «Уведомления» (Safari спрашивает
разрешение только по нажатию). Нажатие на уведомление открывает нужный экран.
Устроено так: `apps/mobile/public/sw.js` (service worker) и `manifest.webmanifest`,
подписка — `src/lib/push.web.ts`, подписки хранятся в `web_push_subscriptions`,
отправляет `notify-dispatch`. При выходе из аккаунта браузер отписывается.
Ключи VAPID лежат в `~/Documents/marketing-keys/vapid.env`:
- публичный — переменная репозитория `EXPO_PUBLIC_WEB_PUSH_KEY` (и в `apps/mobile/.env.local`);
- в секретах Supabase — `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` и `VAPID_SUBJECT`
  (адрес сайта). Без них web push не отправляется, Telegram работает как раньше.
Если ключи сменить, браузеры переподпишутся при следующем входе в приложение.

**Уведомления не уходят вовсе** (в таблице `notifications` пустой `sent_at` и нет `error`):
у базы нет секретов для вызова `notify-dispatch`. Исправляет `./scripts/enable-notifications.sh`
(то же делает шаг 4 `setup.sh`).

**Push в приложении** работает только в собранном приложении (EAS Build), не в Expo Go
на Android. Нужны `npx eas-cli@latest init` (добавит projectId) и ключи Firebase/Apple
при сборке. До этого уведомления приходят в Telegram и web push.

## Публикация и контент-календарь

- У задачи задаются **дата и время публикации**. Всё запланированное видно в
  **контент-календаре**: клиент видит свои публикации, команда — все.
- Кто публикует, выбирается в заказе:
  - **«Наша команда»** — в назначенное время менеджерам и SMM приходит «Пора
    публиковать»; они публикуют и нажимают «Отметить опубликованным» (можно со ссылкой).
  - **«Автоматически»** — публикует сервер в Instagram (см. ниже). Без подключённого
    Instagram работает как «Наша команда».
  - **«Я сам»** — напоминание приходит клиенту; он скачивает файлы и сам отмечает
    публикацию.
- Когда опубликовано всё, заказ получает статус «Выполнен».
- **Ежемесячные заказы:** через 30 дней после оплаты клиенту приходит напоминание
  о продлении; кнопка «Повторить заказ» создаёт такой же заказ по текущим ценам.

## Автопубликация в Instagram

Клиент подключает Instagram в разделе «Соцсети» (нужен профессиональный аккаунт:
бизнес или автор; Facebook-страница не нужна). Дальше сервер публикует сам:

| Услуга | Файлы | Что выйдет |
|---|---|---|
| Пост | 1 фото | пост |
| Пост | 1 видео | рилс |
| Пост | 2–10 файлов | карусель |
| Рилс | видео | рилс |
| История | фото или видео | история |

- Instagram принимает фото только в **JPEG**, видео — **MP4/MOV**. Приложение само
  переводит фото (PNG, HEIC, WebP…) в JPEG при загрузке и уменьшает до 1440 px по ширине.
  Для поста исполнитель сразу видит предупреждение, если пропорции фото не подходят
  для ленты (нужно от 4:5 до 1.91:1).
- Видео Instagram обрабатывает несколько минут: сервер проверяет каждые 5 минут и
  публикует, когда готово.
- Если не получилось (не тот формат, ошибка Instagram, обработка дольше 2 часов),
  менеджеры получают уведомление с причиной. Можно опубликовать вручную или исправить
  файлы и заново поставить дату.
- Токен доступа хранится только на сервере и продлевается автоматически.
- Facebook-страницы пока не поддерживаются.

## Отчёты

Раздел **«Отчёт»** у клиента (у менеджера — кнопка «Отчёт» в анкете клиента) за
последние 30 дней:

- подписчики и их изменение, охват, просмотры, взаимодействия аккаунта;
- охват каждой нашей публикации (лучшая выделена) с лайками, комментариями,
  сохранениями и репостами; нажатие открывает пост;
- сводка работы: опубликовано, запланировано, в работе.

Цифры собираются из Instagram каждые 6 часов (истории Instagram отдаёт только первые
24 часа, поэтому чаще, чем раз в сутки). Публикации, сделанные вручную, находятся по
ссылке, указанной при отметке «Опубликовано». Для статистики нужно разрешение
`instagram_business_manage_insights`; если аккаунт подключён без него, в отчёте будет
просьба переподключить Instagram.

### Настройка Meta (один раз)

1. https://developers.facebook.com → **Create App** → тип **Business**.
2. Добавьте продукт **Instagram** → **API setup with Instagram login**. Там будут
   **Instagram App ID** и **Instagram App Secret** — их спросит `./scripts/setup.sh`.
3. В «Business login settings» укажите **Redirect URL**:
   `https://<ref>.supabase.co/functions/v1/instagram-callback`
4. **Пока приложение Meta в режиме разработки**, подключать можно только аккаунты,
   добавленные как тестировщики (App roles → Roles → Instagram Testers).
   Для реальных клиентов нужен **App Review** на разрешения
   `instagram_business_basic`, `instagram_business_content_publish` и
   `instagram_business_manage_insights`: понадобятся
   политика конфиденциальности на сайте, видео с демонстрацией и верификация бизнеса.
   Обычно это занимает от нескольких дней до нескольких недель.

## Роли и регистрация

- **Владелец** (`admin`) — один на компанию. Только он назначает роли; всё, что может
  менеджер, может и он.
- **Сотрудники:** менеджер, дизайнер, видеограф, монтажёр, фотограф, копирайтер,
  SMM-специалист, таргетолог, SEO-специалист — видят всех клиентов и общий чат команды.
- **Фрилансер** — только свои задачи и данные этих клиентов, личные чаты.
- **Клиент** — свой бизнес, заказы, согласование, чат по заказу.

При регистрации человек выбирает **«Я клиент»** или **«Я сотрудник агентства»**.
Сотрудник попадает на экран ожидания, владелец получает уведомление и назначает роль
на экране «Команда» (блок «Ждут роли») — после этого у сотрудника открывается работа.
Выбрать себе роль при регистрации нельзя.

## Как это устроено внутри

- Права доступа проверяет база (Row Level Security): клиент видит только своё,
  фрилансер — только свои задачи, токены Instagram не видит никто, кроме сервера.
- Смена статусов идёт через функции базы (`create_order`, `assign_task`,
  `client_decide`, `mark_published`…), так что правила не обойти из приложения.
- Уведомления: база пишет строку в `notifications` и сразу вызывает функцию
  `notify-dispatch`. Расписание (публикации, продления, автопубликация, сбор
  статистики) — через pg_cron.
  Адрес проекта и секреты для этих вызовов лежат в Supabase Vault (их кладёт
  `setup.sh`).
